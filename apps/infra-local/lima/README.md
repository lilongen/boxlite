# Lima Runner (`apps/infra-local/lima/`)

This directory brings up a Lima Linux VM on macOS that hosts a
`linux/arm64` `boxlite-runner` over KVM + libkrun — the production-parity
data plane. It's an alternative to the existing M5-native (HVF backend)
runner described in [`docs/apps/infra-local-status.md`](../../../docs/apps/infra-local-status.md).

See the design spec for the full rationale:
[`docs/superpowers/specs/2026-05-26-macos-lima-runner-support-design.md`](../../../docs/superpowers/specs/2026-05-26-macos-lima-runner-support-design.md).

---

## Why Lima vs M5-native?

| Dimension | M5-native runner | Lima runner (this dir) |
|---|---|---|
| Data plane | macOS HVF → libkrun HVF backend → microVM | Lima Linux → KVM → libkrun KVM backend → microVM |
| Production parity | ❌ different libkrun code path than EC2 | ✅ identical libkrun KVM path as EC2 |
| RAM overhead | ~0 (just a host process) | ~2–3 GiB (Lima VM) |
| First-time setup | `/tmp/boxlite-runner` (built on host) | `make lima-up` (Lima creates + provisions VM) |
| Iteration speed after Go change | rebuild + restart on host | `make lima-rebuild` (~30–60s in VM) |
| Use case | Casual day-to-day dev | Verifying prod-side behavior, autoscaler later |

Both can coexist; only start one at a time (the API doesn't enforce
single-runner per region, but mixed scheduling can confuse you).

## First-time setup

Run these three commands once per developer machine:

```bash
# 1. Install Lima + the vmnet helper
brew install lima socket_vmnet

# 2. Grant Lima the sudo permissions it needs for vmnet shared.
#    (Generated by limactl; safe — only allows the socket_vmnet binary.)
sudo chown -R root:wheel /opt/homebrew/opt/socket_vmnet \
                        /opt/homebrew/Cellar/socket_vmnet
limactl sudoers | sudo tee /etc/sudoers.d/lima >/dev/null

# 3. Point Lima's networks.yaml at the Homebrew install path (if needed).
#    Lima's default expects /opt/socket_vmnet — Homebrew installs to
#    /opt/homebrew/opt/socket_vmnet. Edit ~/.lima/_config/networks.yaml and
#    change `socketVMNet:` to "/opt/homebrew/opt/socket_vmnet/bin/socket_vmnet".
```

Verify with `make lima-doctor` from `apps/infra-local/`. Re-run any
failing step until it reports all green.

### Why the chown step?

`socket_vmnet` runs as root via sudo; Lima refuses to invoke it unless
the binary and its parent directories are root-owned (so a non-root user
can't tamper with the privileged code path). Homebrew installs it under
the user account by default, so a one-time chown is required.

## Daily workflow

```bash
cd apps/infra-local

# Bring the runner VM up. ~5 min on first run (Ubuntu image download +
# toolchain install + first cargo build of libboxlite.a). Subsequent runs
# are ~30 s.
make lima-up

# Tail runner logs in another shell while developing.
make lima-tail-logs

# After editing runner Go source on the host, push the rebuild into Lima.
make lima-rebuild

# Drop into the VM for ad-hoc debugging.
make lima-shell

# When done.
make lima-down                  # stop + delete the VM (data lost)
```

The VM is named `boxlite-runner` by default. Override with the
`LIMA_NAME` env var if you want a second instance.

## What lives where

| Path | Purpose |
|---|---|
| `lima/runner.yaml` | Lima VM template — `vmType:vz`, `nestedVirtualization:true`, vmnet shared, source mount, 3 provision blocks. |
| `lima/provision/install-toolchain.sh` | Runs as root in the guest: apt deps + Go + Node + corepack. |
| `lima/provision/build-runner.sh` | Runs as the guest user: rustup + cargo build libboxlite.a + nx build daemon-arm64 + runner-arm64. All build state stays in `$HOME` (never the mounted host repo). |
| `lima/provision/install-runner.sh` | Runs as root: installs binary at `/opt/boxlite/runner`, drops `boxlite-runner.service` from `apps/runner/packaging/systemd/`, renders `/etc/boxlite/runner.env`, `systemctl enable --now`. |
| `../scripts/lima-up.sh` | `make lima-up` impl. Idempotent. |
| `../scripts/lima-down.sh` | `make lima-down` impl. Stop + delete. |
| `../scripts/lima-shell.sh` | `make lima-shell` impl. Pass args to `limactl shell`. |
| `../scripts/lima-rebuild.sh` | `make lima-rebuild` impl. Rebuild from the source mount, restart the unit. |
| `../scripts/lima-runner-update.sh` | `git pull origin main` on host, then `lima-rebuild.sh`. |
| `../scripts/lima-tail-logs.sh` | `journalctl -u boxlite-runner -f` inside the VM. |

## Networking

Lima's `vmnet shared` mode gives the VM its own IP on a `192.168.105.0/24`
(or similar) subnet. From inside the VM:
- Host-published L1 services (postgres on `:25432`, registry on `:25000`,
  dex on `:25556`, otel on `:24317`) must bind `0.0.0.0` (not `127.0.0.1`)
  to be reachable via the vmnet gateway.
- Reach the host via `ip route | awk '/^default/{print $3}'` — typically
  `192.168.105.1`.

From the host:
- Reach the VM via `limactl list boxlite-runner` (look for the address).
- The runner registers with the API using its vmnet IP as
  `RUNNER_DOMAIN`, mirroring EC2's `HOST_IP` semantics.

## Verification checklist (clean-state preconditions for `make lima-doctor`)

Three observable preconditions for a clean reproduction:

1. `brew list lima socket_vmnet` shows both packages.
2. `/etc/sudoers.d/lima` exists, owned by root, mode 0644.
3. `~/.lima/boxlite-runner/` does NOT exist (i.e. `make lima-down` was
   run before the test).

Then `make lima-up && make lima-doctor` must report all green.

## Troubleshooting

### `/dev/kvm` missing inside the guest

Confirms nested virt isn't active. Check:
- `apps/infra-local/lima/runner.yaml` has `vmType: vz` AND
  `nestedVirtualization: true`.
- Hardware: M3 silicon or newer.
- macOS: 15.0 or newer.

### L1 services unreachable from inside Lima

Symptom: `make lima-doctor` reports `unreachable from Lima: postgres,
dex, ...` even though the L1 boxes are running. Cause: those services
bound to `127.0.0.1` only.

Fix: edit `apps/infra-local/boxlite_local/services.py`, find the
affected `ServiceSpec`, and change the `ports` to bind `0.0.0.0`. Then
`make stack-rebuild-l1-box BOX=<name>`.

### Host repo `git status` shows new files after Lima build

Means `build-runner.sh` didn't redirect a build cache into `$HOME`.
Check the `NX_CACHE_DIRECTORY` / `GOMODCACHE` / `CARGO_TARGET_DIR` /
`YARN_CACHE_FOLDER` exports at the top of that script. All build state
should land in `/home/${USER}.linux/.cache/` or similar, never on the
mounted source tree.

### `socketVMNet` "not owned by root" error

```
fatal msg="networks.yaml field `paths.socketVMNet` error: file
\"/opt/homebrew/opt/socket_vmnet/bin/socket_vmnet\" is not owned by root"
```

Run the chown step from §First-time setup.

### `limactl sudoers` says "has to be installed at /opt/socket_vmnet"

Edit `~/.lima/_config/networks.yaml` and set:
```yaml
paths:
  socketVMNet: "/opt/homebrew/opt/socket_vmnet/bin/socket_vmnet"
```

## What this branch did NOT do (out of scope)

Per the design spec §7:

- `LimaInfraProvider` in NestJS — separate branch.
- Multi-Lima support — separate branch.
- Take the M5-native runner offline.
- Update `apps/runner/Dockerfile` for arm64.
- arm64 release tarball on GitHub Releases.
- `mount-s3` / sandbox-volume-from-S3 parity.
